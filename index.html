Research brief · 09 Oct 2026Windows · Claude Code · Bevy 0.19

Don’t install a harness. Assemble the right one.

For a GameCube-era 3D port, the best fit is Claude Code’s native loop—subagents, hooks, skills and MCP—paired with Bevy Remote Protocol tooling. The purpose-built game harnesses are either the wrong engine, the wrong platform, or ideas rather than installable software.

Recommended stack

Claude Code native + Bevy BRP MCP + a cold critic + cargo gates.

04

Can Claude delegate to local AI?

Yes—with a proxy and carefully scoped roles. It is practical for cheap extraction work, not the core Rust/Bevy reasoning.

The concrete route

LiteLLM can expose an Anthropic-compatible endpoint to Claude Code while routing selected aliases to Ollama, LM Studio, or a llama.cpp server.

Claude Code
  → LiteLLM on localhost:4000
    → haiku alias → local coder model
    → sonnet/opus → Anthropic
Small local models have weaker tool-calling reliability. Keep them on extractor-style tasks.

The hard parts combine the borrow checker, ECS design, fast-changing Bevy APIs, and long-horizon reasoning. A bad local edit can cost more in rebuild loops than it saves.

05

What not to bother with—yet

Genex

Revisit only after Windows and a Bevy/Rust or native-target plugin exist.

tmux orchestration

Built-in subagents and background tasks avoid WSL2 complexity for this setup.

Engine-mismatched MCPs

Unity and Unreal tools are useful patterns, but their bridges do not transfer.

06

What still needs a local proof

  • Whether joaqim/bevy_mcp works end-to-end with Bevy 0.19; its README targets 0.18.
  • grok-bevy’s practical screenshot quality and Bevy 0.19 compatibility.
  • Genex’s Windows release date and any Bevy roadmap beyond stated Unity/Unreal plugin plans.
  • Real token cost for Agent Teams on a port of this scale.
  • A mature Blender-specific MCP was not researched; the recommendation remains Blender’s Python API through Claude Code.
