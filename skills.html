Research snapshot · 10 Oct 2026

Build the skill stack around the port.

For this Bevy 0.19 project, the best answer is not one giant plugin. Use a tight set of version-pinned Rust, Bevy, BRP, asset-pipeline, and task-claiming skills—then keep project rules in the repository.

Bottom line

Install one workflow, adapt three core skills, write three project skills—including task coordination—and keep one shader skill optional.

No public Bevy skill covers this exact Windows + 0.19 + classic-game-port setup end to end.

02 / COORDINATION

Stop duplicate work at the claim

Built-in Agent Teams coordinates Claude Code sessions. It does not span Muse and Claude Code CLI, so the durable contract must live in the project.

Recommended: one shared TASKS.md

Each agent reads the file first, claims one item before touching code, and writes a completion record. This is simpler and more transparent than asking two independent runtimes to infer each other’s state.

  1. Claim before code. Change an available item to a claimed state with assistant or claude-code.
  2. Own one clear surface. Include files or subsystem boundaries in the task text.
  3. Finish with proof. Record the commit and verification command, or mark a concrete failure reason.
  4. Reclaim stale work. A claim older than 24 hours is reclaimable after checking the branch and working tree.
Windows choice: edit the file directly or port the atomic claim helper to PowerShell. The public opus-orchestra helper is a .sh script and therefore needs Git Bash or WSL.
# TASKS

## Available
- [ ] Port villager schedule data
  owner: —
  scope: src/villager/schedule/**
  verify: cargo test villager::schedule

04 / AVOID DRIFT

Skip these as-is

Some are useful references, but installing them unchanged would add stale APIs or unnecessary machinery.

Genex skill

It is an AI asset-generation service—not a Bevy porting skill. It adds an external paid dependency and sign-in, and it is a poor fit for faithful GameCube-era asset reproduction. View source

bevy-ecs from gamedev-skills

Its Bevy 0.16+ guidance is too old for a 0.19 project and risks teaching stale APIs. Engine-agnostic discipline skills from the same collection may still be useful.

trobanga Bevy skill, unchanged

Excellent reference material, but targeted at Bevy 0.18. Mine its ECS and glTF pitfalls only after doing a 0.19 delta pass.

Full actionbook/rust-skills plugin

Evaluate rather than install by default. Its large meta-cognition framework overlaps the focused rust-workflow this project needs and may be overkill.

Agent Teams for Muse ↔ Claude Code handoff

The experimental built-in feature coordinates Claude Code sessions only. Use it later for multiple Claude Code teammates, not as the cross-tool source of truth.

05 / INSTALLATION

How Claude Code finds skills

Official Claude Code documentation was read live on 10 Oct 2026. Project scope is the right default because the skill travels with the repository.

  1. Create one directory per skill.Use .claude/skills/<skill-name>/SKILL.md. Optional helpers belong in sibling scripts/, references/, or assets/.
  2. Add YAML frontmatter.description is recommended and drives automatic matching. Useful fields include name, when_to_use, shell, tool limits, paths, model, and hooks.
  3. Prefer PowerShell on Windows.Set shell: powershell when a skill embeds commands and the machine is not relying on Git Bash.
  4. No registration is required.Claude Code auto-discovers the directory. Invoke with /skill-name or let the description match the task. For a brand-new top-level skills directory, run /reload-skills.

├── SKILL.md
└── references/

06 / VERIFY BEFORE INSTALL

Open questions

These are genuine gaps in the research. Resolve them at installation time rather than guessing.

Which exact Bevy 0.19.x is in Cargo.toml?

Baylee pins 0.19.1, but the project’s actual dependency is authoritative. Re-check docs.rs and migration notes against that pin.

What edition, MSRV, and features are configured?

The project file was not part of the research. Read Cargo.toml; do not inherit Baylee’s Rust 1.95 assumption blindly.

Can grok-bevy’s playbook be copied directly?

Its files live under .grok/skills/; direct Agent-Skills-format compatibility was not confirmed. Inspect and rewrite if necessary.

Which porting conventions are already settled?

Module boundaries, timing, asset roots, determinism, and renderer/game-logic separation should reflect project decisions, not public templates.
